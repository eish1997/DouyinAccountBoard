## 已固定的采集契约 C01

首版编译代码默认且强制禁用执行能力，环境变量不能重新开启；恢复采集须另行授权和验收后修改版本。
GET collection/status 可供登录用户查看保留统计，返回 enabled=false、can_manage=false；GET领取与所有collection POST在读取数据库或鉴权令牌之前返回503及 COLLECTION_DISABLED。
服务层 enqueue/next_job/complete/heartbeat同样拒绝，旧有效令牌也不能执行。
启动不得重排running任务；任务、作品数、时间、错误、历史保持。Worker Python及PowerShell入口在任何配置/profile读取前拒绝。
界面禁用执行控件并显示采集暂未启用，继续展示历史数据。

- 幂等唯一键：(恢复代次, 用户ID, 请求ID)，绑定动作与规范化摘要；成功结果与业务同事务提交。冲突、未找到、处理中、成功、失败、旧代次分别返回；结果详情拟保留30天，去重墓碑保留至该代次关闭；无授权不返回历史结果。
- 维护状态、写入版本围栏、恢复代次和人员授权在共享存储；发布默认维护；旧实例版本不匹配拒写。恢复失败保持维护，手动解除。
- 业务逻辑恢复与整库灾备分开；业务恢复显式表白名单，不回滚授权/会话/控制/幂等；采集任务作为历史恢复，令牌与执行资格不可复活。

- 结构迁移仅受控工具执行；全量逐字段、行数、键、图片、权限JSON、中文、前导零、NULL/空串、排序、时间及序列核对，报告只输出摘要。

## PostgreSQL 优先评估补充

2026-10-21 官方搜索结果提供了此前打开超时页面的正文。CloudBase PG有协议直连、复杂SQL/事务/连接池文档，适合继续复用Python后端；不用把现有鉴权改成CloudBase Auth，也不把前端直接连库作为默认方案。[连接数据库](https://docs.cloudbase.net/database/postgresql/connecting-to-postgresql)

建议候选架构：CloudBase Run → Python PostgreSQL驱动/连接池 → 独立业务schema；现有auth_users/auth_sessions为本应用表，不能覆盖平台auth/storage schema。账号只获得本业务schema必要权限；匿名/客户端角色不得直接读取业务表。直连地址、CA、TLS方式、版本、连接限额必须以实际环境确认，不能照抄示例关闭证书验证。[PG能力和权限模型](https://docs.cloudbase.net/database/postgresql/initialization)

实例候选：50人持续工作负载优先评估独享实例，最终规格由固定负载报告决定；共享实例是否足够不作猜测。地域与规格可用性以控制台为准。[数据库管理](https://docs.cloudbase.net/database/postgresql/database-management)

恢复方案候选：应用全库（仅本业务schema，含本应用身份表）使用一致性pg_dump/pg_restore；业务恢复使用显式业务表逻辑manifest。原生pg_dump具备一致快照，但这不能证明CloudBase授予了所需权限、允许导出全部应用对象，或已满足RPO/RTO。[PostgreSQL SQL备份](https://www.postgresql.org/docs/current/backup-dump.htm)

关键未决：未找到明确适用于CloudBase PG当前套餐的PITR、备份下载、跨故障域保留及恢复时长承诺。搜索返回的database/backup明确属于文档型数据库，tdsql/backup属于MySQL，不能借用为PG证据。可评估每15分钟独立作业生成应用快照上传独立存储，但必须实测生成+上传+重试，使最后可恢复点≤1小时；不得用“每小时启动”替代恢复点验收。

解除T00平台信息缺口需要：PG主版本/实例类型、可售地域、直连网络与TLS证书要求、最小权限账号能力、备份导出/PITR说明、连接上限及报价。不需要提供密码、连接串或客户数据。未明确前只做通用SQL风险盘点及不依赖数据库的开发。

本机环境探测：存在docker.exe，普通沙箱访问引擎管道拒绝；已尝试只读版本探测（不列出或读取其他容器），结果另记evidence。未安装或启动数据库、未读取已有数据库。
